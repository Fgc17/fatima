### Loading secrets

Before loading or generating secrets, run `fatima init` once in the project root. Fatima requires `fatima.json` for every command except initialization.

To load local secrets in your app, use the `registerAsync` function generated in your `env.ts` file.

```ts
import { env, registerAsync } from "./env";

async function main() {
  if(env.ENVIRONMENT === "development") {
    await registerAsync();
  }
}
```

This loads `.env` by default and updates the generated `env` cache before you read values.

Make sure to only run this in development. In production, load secrets through your hosting platform or process manager, not through Fatima.

### Loading secret synchronously

If you need to load secrets synchronously, use the generated `register` function.

```ts
import { register } from "./env";

register();
```

### CI/CD

Before building your app, you need to run `fatima generate`.

In CI/CD environments, all needed secrets should already be available as environment variables, so all you gotta run is

```bash
npx fatima@latest generate --process-env
```

The `--process-env` flag tells Fatima to load secrets from the environment variables instead of the `.env` file, which is the default behavior.

In case you need custom loading behavior, define a plugin provider and reference it from `fatima.json`.

### CLI vs API

Previously, Fatima had two commands: `fatima run` and `fatima dev`.

Both of them were responsible for loading secrets and running your app, but they had different use cases.

Fatima dev was intended for long running processes, like a your development server, while `fatima run` was intended for one-off commands, like a migration or seeding script.

Ultimately the library evolved and now discourages the usage of CLI to load secrets, `fatima dev` was deprecated and `fatima run` should only be used when you want to test something, or when you need to inject secrets in a process you don't control.

Generally, we should avoid enveloping processes with other processes. That's why app code should use the generated `./env` SDK instead of importing from `fatima`.
